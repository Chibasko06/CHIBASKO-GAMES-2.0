# Convention de rédaction

Ces règles s'appliquent à toutes les modifications du projet.

- Rédiger le code, les commentaires, la documentation et les messages du point de
  vue du projet. La documentation interne décrit ses décisions, contraintes,
  procédures et limites, sans raconter les échanges ayant produit les fichiers.
- Formuler les étapes de maintenance comme des procédures techniques. Les
  contrôles de release et les prérequis de déploiement restent explicites, sans
  présenter le responsable du projet comme un interlocuteur extérieur.
- Réserver les commentaires aux invariants, raisons de conception, contraintes de
  sécurité et comportements non évidents. Supprimer les commentaires redondants.
- Formuler les TODO/FIXME comme des tâches techniques précises.
- Conserver les formulations adressées au lecteur dans la documentation publique
  et les interfaces. Les rôles métier, termes d'API et identifiants gardent leur sens.
- Préserver le texte des licences et ses pronoms juridiques. Une correction de
  style ne doit modifier ni les droits accordés ni les conditions applicables.
